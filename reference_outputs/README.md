# reference_outputs/

Compact outputs from the validated corrected production run
**`20260909T010240Z_194231425561_909244de`** (analysis source commit
`1942314255619`, status `complete`, validation `passed`).

**These are reference material for verification only. They are not inputs to
the analysis and are not required to run it.** Reproducing the analysis
regenerates equivalents under a new `production_runs/<run_id>/staging/results/`
directory.

## Contents

- `results/` — the 23 result CSVs the run produced, in their original relative
  layout: the 5 sex summaries, the age and race decomposition outputs, the
  supplementary threshold and case-mix outputs, and the four
  `jama_reporting/` files that are the data behind Table 1, Figure 1, and
  eTable 1 of the manuscript.
- `run_manifest.json` — protocol, environment and package versions, input
  SHA-256 checksums, the executed command plan, output verification, and the
  reproducibility acceptance policy.
- `provenance.jsonl` — one analytical record per dataset-attribute comparison,
  including the ordered predictor names, training-derived imputation values,
  categorical schemas and reference levels, partition sizes and event counts,
  candidate-family cross-validation scores, the selected family, seed,
  operating threshold, calibration configuration, and, for Diabetes-130, the
  unique patient counts per partition with verified patient overlap.

Figure image files from the run are **not** included, to keep the repository
small. They are regenerated by rerunning the analysis.

## Path redaction

`run_manifest.json` and `provenance.jsonl` originally recorded the absolute
path of the Python interpreter and of the project directory on the machine
that produced the run. Those strings contained a local operating-system user
name and directory layout, so they were redacted before publication:

- `environment.python_executable` -> `python`
- absolute interpreter and project-root prefixes inside recorded `argv`
  entries -> `python` and `<project-root>/`

**75 path strings were replaced across the two files. No other value was
changed**, verified by comparing every scalar leaf before and after: 10,457
non-path values, including every input checksum, protocol field, model
selection score, partition count, and metric, are byte-identical to the run's
own records.

## Note on the provenance records

`provenance.jsonl` contains a small number of records whose `command_id` ends
in `unit_tests`. Those are from synthetic fixtures used by the validation
suite, not real analyses, and the reporting code filters them out. The 20
records from the analysis commands are the real ones.

## Verification

After a reproduction run, compare your `staging/results/` against
`reference_outputs/results/`. The run's own acceptance policy is
tolerance-based rather than bitwise; see the `reproducibility_acceptance`
block of `run_manifest.json` and the reproducibility section of the top-level
README.
